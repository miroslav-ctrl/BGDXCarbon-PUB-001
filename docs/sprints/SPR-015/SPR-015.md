## Why this sprint

src/bgdxpublisher/cli/batch.py currently calls legacy publishing.batch.publish_batch with PublishingService. SPR-014 already supplies BatchHtmlPublicationService, immutable item/index outcomes and runtime registration. SPR-013 migrated the single HTML CLI route; the corresponding batch route is the remaining integration gap. No existing SPR-015 issue or plan was found in the repository at baseline.

## Goal

Route the existing publish-batch command through the registered BatchHtmlPublicationService. Preserve parser/options, deterministic outputs and successful stdout contract; map typed failures into safe, documented CLI diagnostics. Keep each document and index commit independent.

## Scope

Change the CLI adapter, focused CLI regression tests, installed-wheel smoke checks and user documentation. Reuse BatchRequest, JobStatus and the current batch service. No new runtime package or dependency is planned.

## Exclusions

No batch engine rewrite, legacy direct API migration, new command/options, recursive discovery, DOCX/PDF integration, parallel execution, retries, cancellation, persistence, rollback, version bump or release. No implementation, issue creation or merge is performed by this planning PR. main is outside scope.

Deliverables: CLI integration, tests, user-facing error documentation, CI wheel scenarios, implementation evidence and final acceptance/closure records. See IMPLEMENTATION-SPEC.md, ACCEPTANCE.md, VERIFY.md and REVIEW-CHECKLIST.md.

## Risk and decision

Expected operational stderr intentionally changes: legacy source paths/raw exception text will be replaced by stable codes and safe item ordinals. Successful stdout stays compatible. Consumers parsing old errors must be informed in USER-GUIDE and CHANGELOG. A shutdown failure will suppress buffered success output, while retaining already committed files; this is an explicit proposed behavior requiring plan review.
