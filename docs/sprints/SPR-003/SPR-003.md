# SPR-003 – Publisher Core and Document Publishing Foundation

## Publisher domain and pipeline foundation

The Markdown-to-HTML publishing behavior documented below is already shipped
and remains unchanged. This extension adds an immutable document model, validated
publisher jobs, and a deterministic in-process pipeline alongside the existing
publishing, CLI, runtime, configuration, logging, and service-registry modules.
It does not add a second CLI or perform rendering, filesystem, network, database,
or external publishing work.

Documents have UUID identifiers, a supported document type, non-empty title
and source reference, recursively immutable JSON-compatible metadata, and a
timezone-aware creation timestamp normalized to UTC. Document and job request
validation returns stable field-specific error codes.

Jobs follow `CREATED → VALIDATED → QUEUED → RUNNING → COMPLETED`; a job may
transition to `FAILED` from any nonterminal state. Invalid transitions raise a
typed domain exception. Jobs remain immutable; lifecycle transitions return a
new job instance.

Pipeline stages run sequentially in their declared order and must declare input
and output types. Failures raise a typed exception carrying a structured failed
result, completed-stage identifiers, and the original exception as its cause.
Failed results never expose partial output as a completed result. Registered
cleanup callbacks run in reverse order. An empty pipeline returns its input as
a successful no-op.

## Goal

Publish a local UTF-8 Markdown document as a standalone HTML document through
the existing CLI, runtime, configuration, logging and service registry.

```sh
bgdxpublisher publish document.md --output document.html
bgdxpublisher publish document.md --output document.html --overwrite
bgdxpublisher publish document.md --output document.html --config custom.yaml
```

Headings, paragraphs, ordered/unordered lists, emphasis, links, block quotes
and fenced code are supported. Styles are embedded; no network request is made
during publishing. Images become alternative text. Raw HTML is escaped and
unsafe links are left as text. No remote resources are loaded by the output.

Output parents must already exist. No implicit directory creation or file
replacement occurs. Publishing never modifies the input. Existing output needs
`--overwrite`. Equal paths, hard-link aliases, symbolic output links and
nonregular files are refused. Exit codes: 0 success, 1 expected operational
error, 2 invalid arguments. A cleanup failure after publication returns 1 and
reports the cleanup problem; the completed output remains available.

PDF/DOCX, user templates, batch publishing, plugins, GUI/web, authentication,
cloud storage and hosting remain outside this sprint.
