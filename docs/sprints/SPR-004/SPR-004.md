# SPR-004 — HTML Document Metadata

Adds `--title` and `--lang` to the existing publish command. By default, the HTML
browser-tab title remains the input filename stem and language remains `und`.
Metadata does not change the Markdown heading or body.

Example:

```sh
bgdxpublisher publish document.md --output document.html --title "Izveštaj" --lang sr-Latn
```

The typed PublishRequest carries optional title and language. The renderer validates
metadata for both CLI and direct service callers. Titles must contain non-whitespace
text and cannot include control characters or Unicode line/paragraph separators.
HTML metacharacters are escaped rather than interpreted.

The supported language syntax is a 2–3 letter primary language, optional four-letter
script, optional two-letter or three-digit region, followed by optional variants
(5–8 alphanumeric characters, or four characters starting with a digit). Examples:
`sr`, `sr-Latn`, `sr-Cyrl-RS`, `en-US`, `es-419`, `de-CH-1901` and `und`.
This is a documented subset of BCP 47 syntax, without registry lookup or language
detection. Extensions, private-use and grandfathered tags are outside this sprint.
Case is retained. Invalid CLI metadata exits 2; invalid service metadata raises
PublishingError before staging or replacing output. Source bytes stay unchanged.

PDF/DOCX, templates, batch processing and UI are outside scope.

Review correction: repeated language variants are rejected case-insensitively
(e.g. de-CH-1901-1901 and sl-rozaj-ROZAJ). CLI diagnostics retain the validator's
specific title, language-syntax or duplicate-variant message and exit code 2.
