# SPR-001 – Runtime Foundation

## Goal

Implement the EAS 1.0 runtime foundation without adding document processing,
publishing, plugins, GUI, API, or PDF functionality.

## Scope delivered

- Runtime metadata, context, lifecycle states, application orchestration, and
  domain exceptions.
- Immutable Pydantic v2 settings, safe YAML loading, named environment overlays,
  and `BGDXPUBLISHER__...` environment variable overrides.
- Structured UTC JSON output through standard Python logging, with console and
  optional file handlers.
- Type-keyed service registration with duplicate and type-mismatch protection.
- Focused unit tests for the runtime, configuration, logging, and registry.

## Configuration

The default file is `configs/default.yaml`. Configuration can contain an
`environments` mapping whose selected entry deep-merges over the base values.
Select an environment using the `environment` argument or `BGDXPUBLISHER_ENV`.
Nested values can be overridden with variables such as
`BGDXPUBLISHER__LOGGING__LEVEL=DEBUG`.

Settings are validated and frozen when loaded. A configuration service accepts
only one successful load.

## Runtime metadata and lifecycle

The normal lifecycle is `CREATED` → `INITIALIZING` → `CONFIGURED` → `RUNNING` →
`STOPPING` → `STOPPED`; failures from active preterminal states enter terminal
`FAILED`. `ApplicationMetadata` carries configured application name/version
and the selected environment. Build/release/vendor/contact/license metadata is
deferred because those fields are not defined by the approved repository
configuration contract.
