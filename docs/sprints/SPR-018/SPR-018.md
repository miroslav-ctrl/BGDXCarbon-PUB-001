## Goal and boundaries

Add a separately registered PDF pipeline Python API with immutable results,
fresh jobs/contexts, typed stages and safe structured failures. Keep publish-pdf
and legacy PdfPublishingService unchanged. CLI migration is a separate future
sprint requiring its own approved compatibility plan.

Scope: new pdf_pipeline package/tests, runtime registration, installed-wheel API
example, eighth independent coverage gate and documentation. No CLI/parser,
renderer/font/writer/engine rewrite, batch PDF, new options/templates/assets,
retry/queue/storage/parallelism/rollback, dependency addition, version bump,
release/tag or main change. Preserve existing seven gates and all command checks.

README.md Publisher core API/Scope and docs/RELEASING.md contain historical claims
that rendering is not integrated. Future implementation documentation must align
these with actual HTML/batch/DOCX integration and distinguish PDF API from CLI;
do not reinterpret historical release scope as current architecture.
