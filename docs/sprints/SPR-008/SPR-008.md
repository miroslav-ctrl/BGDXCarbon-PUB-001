# SPR-008 — Batch HTML index

`publish-batch --index` additionally creates `OUTPUT_DIR/index.html` using the
selected theme and document language. Without `--index`, existing CLI behavior
and document output bytes are unchanged. The index has title `Documents` and
English interface text marked `lang="en"`; document labels inherit the selected
language. Links use filename stems as plain text and encoded relative filenames
prefixed `./`, preserving Unicode, spaces, `%`, `#`, and Markdown punctuation.
The standalone shell shares the document CSP and embedded CSS. No scripts or
external assets are needed. `--toc` applies to documents, not the index list.

Entries include only successful publications from this invocation, in batch
order. Failed or stale outputs are omitted. If every document fails, an empty
index with an explicit message is generated; exit remains 1. Empty input still
fails preflight and generates no index. Counts refer only to source documents;
index success or failure is reported separately and index failure returns 1.

With `--index`, case-insensitive `index.md`/`INDEX.MD` inputs are rejected before
publishing. Existing index requires `--overwrite`; symlink/directory destinations
and hard-link aliases of inputs or document outputs are rejected at preflight.
Atomic index writing reuses the existing writer, including no-clobber race
protection and POSIX permissions. Documents remain published if index writing
fails. This is per-file atomicity, not a transaction or filesystem race lockdown.

The internal batch API now returns `BatchResult` with `items`, `index`, and
`index_error` instead of a tuple of items. Runtime registration is unchanged.

Acceptance: metadata/themes, deterministic links, escaping, partial and total
failure, reserved names, existing index protection, index commit failures and
races, source preservation, installed-wheel CI, and >=99% test coverage.
