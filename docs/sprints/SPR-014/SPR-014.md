# SPR-014 — Batch HTML Publishing through Job Pipeline

Status: planned. Implementation issue [#31](https://github.com/miroslav-ctrl/BGDXCarbon-PUB-001/issues/31).
Baseline: develop 8bff0cf32a03a74eb5be01277354c2a7f1f6cdd0 after closed SPR-013.

## Goal and scope

Add BatchHtmlPublicationService using existing BatchRequest and HtmlPublicationService. Execute one independent document job per attempted file, sequentially and in deterministic order, with immutable aggregate results and separate index outcome.

Reuse existing HTML/index renderer and atomic writer; minimally share preflight logic where necessary. Add runtime registration, Python API example and installed-wheel checks. Existing publish-batch CLI and legacy batch API keep their current routes.

## Implementation plan

1. Review aggregate contracts, preflight boundaries, item/index failures and acceptance matrix.
2. Extract only needed discovery/collision helpers with legacy regression tests.
3. Implement sequential per-item orchestration and typed aggregate results.
4. Implement independent index result and failure handling.
5. Add differential, partial failure, race, cleanup and safe-log tests.
6. Add runtime registration, executable API example and independent coverage/wheel checks.
7. Review implementation PR to develop; after separately authorized merge verify exact merge SHA CI and record closure before closing #31.

## Exclusions

No CLI migration, DOCX/PDF batch, parallelism, retry, cancellation, durable queue, storage, version change or main changes. Planning documents complete no implementation acceptance criterion.
